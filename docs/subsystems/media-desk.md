# Media Desk

English | [中文](media-desk.zh.md)

## Summary

Media Desk collects source material, edits registered Notes works, and produces scripts and media through continuing native DSH Sessions. The workbench keeps production, scheduling and review beside the accepted work. Platform publication remains manual.

## Package and execution

[@winterhuan/dsh-media-desk](../../plugins/dsh-media-desk/README.md) is one independently installed Host and Client bundle. DSH owns each work Session, the separate global Session, native input, model selection, tools, questions and approvals. Media Desk retains their actual associations and supplies a creative preset. The client renders the official conversation factory in its own Session scope; opening or closing a panel changes subscription rather than Agent ownership.

The Host accepts creation attempts and validated business operations. Native turns supply text candidates; independent image workers consume accepted planning and their own frozen service settings. Attempt and material identities prevent late outputs from replacing incompatible edits. Export reads one accepted snapshot into a fresh directory.

The bundled [Media Desk skill](../../plugins/dsh-media-desk/README.md#shared-skill) owns the shared creative workflow. Native contexts and stage requests load its instructions. Agents edit content files directly. The npm CLI shares the plugin package and reads registration and current bytes without accepting edits. The plugin projects valid changes to registered files and discovers valid rule proposals for pending registration; registration of other new files and operational state remain plugin-owned.

The global [image-generation skill](../../plugins/dsh-media-desk/README.md#global-image-skill) owns image-channel routing and shared execution scripts. Media Desk owns work-specific visual briefs, task scheduling and accepted asset identities; background workers pass frozen image settings to the global executor. Independent images return files for explicit Media Desk registration. Byte validation does not establish visual quality.

DSH defaults initialize new Session models; binding recovery validates the recorded native Session without dispatching model input. Production checks the current model before dispatching input. See the [package contract](../../plugins/dsh-media-desk/README.md#native-conversations).

## Content and acceptance

Registered Notes files own current work text, collected sources, writing preferences and accepted media. Media Desk owns references, receipts, production metadata and raw metrics. Source material remains distinct from the current work. Native file tools own ordinary Agent edits; a read-only validator checks their format, and Store reads adopt valid changes. Session evidence establishes native execution; a durable business receipt establishes structured-stage acceptance. Independent skill requests freeze content and preferences and accept validated outputs with their own receipts, without synthetic native turns.

Works can turn accepted edits into writing rule proposals with evidence. Reviewed enabled rules feed the next production and its per-rule checks; see the [writing rule guide](../../plugins/dsh-media-desk/GUIDE.md#use-the-five-views) for the workflow and check limits.

The Host holds cooperative ownership of its local data directory and saved Notes roots. Nonparticipating editors require byte checks and retained conflict versions. File publication and Store acceptance use a recovery journal; they are separate operations. Wiki knowledge maintenance follows the effective skill and workspace instructions, while accepted creative material does not acquire knowledge authority from its location.
