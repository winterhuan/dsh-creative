# 明确请求时使用朱雀检测

用户要求检测后才能进入此流程。说明章节全文会发送至腾讯 EdgeOne Makers；一次多章前说明范围和预计用量，获得对应授权。只检测时不改文，检测分数只供参考，不决定章节验收或驱动自动重试。

## 通道

先调用 `story_produce_status`，检查 `configured` 列表是否包含 `MAKERS_API_KEY`。已配置时用 `story_zhuque`：

```json
{
  "entry": "story-zhuque",
  "argv": ["--json", "--out", ".story-polish/第12章/R0.json", "正文/第12章.md"],
  "workdir": "<小说目录>"
}
```

`MAKERS_API_KEY` 由 DSH 注入，可在创意生产设置中配置；不在对话索要或输出密钥，不通过 shell 读取凭据。普通 shell 看不到变量不代表工具未配置。

未配置或调用失败时说明实际原因，用户可自行在朱雀网页检测并提供报告；网页有真人验证码，不自动提交或绕过。字段、限制与网页方式见 [检测通道](zhuque-detect.md)。

## 结果

- 退出 0 或 1 都是有效检测结果，分别表示低于或达到报告阈值；均不表示小说验收通过或失败。
- 退出 2、3、4 分别表示输入、凭据或服务问题，不是检测结论。
- 默认最大 20000 字符，少于 350 计数字拒绝提交；更大范围须先确认，不静默加大限制。
- 记录实际消耗和报告位置。片段定位失败时标记待复核，不虚构原文位置。

用户同时要求润色时，根据具体原文问题按 `story-polish` 本地流程修订。检测提示没有对应读感问题时保留原文。复测属于新的全文外发，只在用户授权范围内执行，不自动追分循环。
