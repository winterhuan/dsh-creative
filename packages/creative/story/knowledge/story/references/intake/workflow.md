# 接入已有小说

接入的目标是让已有正文可以继续创作，不要求先做全书分析。先检查源文本、目标位置、最后完整章节和现有工程状态。

## 已有工程

已有 `正文/` 或 `正文.md`、设定和大纲时直接复用，只补本次工作缺少的资料。已有 `追踪/_tracking-state.json` 时运行追踪检查，不删除或重新初始化；正文与追踪冲突要定位原因，不用重导入掩盖冲突。

## 原始 TXT 或 Markdown

1. 保留源文件，在用户指定目录组织正文。长篇确认章节边界，保留标题、顺序和正文，不能把目录、番外或未完成片段误计为完整章；边界不清时询问。短篇保持一个 `正文.md` 即可。
2. 根据已有设定、结尾附近正文和相关前文，确认续写位置与当前人物关系、未解决事件。只追溯本次续写需要的事实，不为初始化生成逐章拆解、全书细纲或每章摘要。
3. 把可核验的当前设定与待确认问题分开。未读范围明确标记，不把猜测写成角色快照或作者真相。用户另行要求深入分析时使用 `story-analyze`。
4. 长篇需要正式续写且没有追踪时，读取 [追踪事务](../writing/long/tracking-transaction.md)，通过资源根目录下 `scripts/tracking_commit.py init --project <小说目录> --input <初始化事务.json>` 一次初始化。`last_chapter=N` 是最后完整章号，不能写成抽样或已分析的章数；第 1..N 章不伪造逐章记录，正常续写从 N+1 开始。
5. 补续写章所需细纲，进入 `story-write`。仅整理原文或导出时无需初始化追踪。短篇不建立长篇 tracking。

初始化所需当前事实不足时，先补相关原文或请作者确认；已完成的正文整理仍可交付，不编造状态来强行通过校验。原著人物、世界观和本书基线留在本书工程，不自动复制成外部对标。

需要将**已有分析结果**补成工程资料时，可选读 [长篇映射](structure-mapping-long.md) 或 [短篇映射](structure-mapping-short.md)；这些映射不构成接入前置步骤。

## 导出与改编来源

长篇需要单一原文时执行资源根目录下的脚本：

```text
python3 <资源根>/scripts/export_novel_txt.py --story-root <小说目录> --out-dir <导出目录>
```

输出 `原著.txt` 与 `章节映射.json`，保留映射让下游片段可以回到章节文件。短篇可直接使用 `正文.md`。

`record_lineage.py` 在工作区根的 `改编谱系.jsonl` 追加来源指纹记录：

```text
python3 <资源根>/scripts/record_lineage.py --workspace-root <工作区> --from-domain novel --from-path <原著路径> --to-domain <目标领域> --to-path <目标路径>
```

需要记录改编取舍时附 `--decision`。接收改编输入时可以记录尚未创建的目标项目；媒体交付只记录实际完成的复制，不把计划当成果，不覆盖已有谱系。下游插件也持有独立的辅助脚本，无需跨插件调用本包。
