# 创作委派

简单工作由当前会话完成；需要独立专业任务时，委派明确加载 `story-write`，传本 Skill 绝对路径、CLI 路径、父工作区、直接子目录作品名、用户约束、输入材料、产物路径和成功条件。子 Agent 先读所选 Role，再按问题读本地参考，不预载全部资料。

| 专业任务 | 本地 Role |
|---|---|
| 全书、卷纲、世界观与结构 | [架构师](roles/story-architect.md) |
| 角色、动机与对白 | [人物设计](roles/character-designer.md) |
| 正文及定点重写 | [写手](roles/narrative-writer.md) |

事实查询/外部研究委派加载 `story`；源文提取加载 `story-analyze`；独立审稿/连续性核查加载 `story-review`。各任务读取所属 Skill 的 Role，不跨 Skill 读取私有参考。跨任务交接提供事实、来源与缺口，不复制整份方法手册。

子 Agent 的 Session 工作区保持父工作区，作品路径是 `{工作区}/{作品名}/`。前置任务前台运行并等待结果；只有无依赖的任务可并行，写作、审稿、修订、提交按依赖推进。文件由明确执行者负责，写手不直接提交追踪。

Team 仅用户明确要求时使用，复用已有成员；同一 Agent 换 Role 不能充当独立评审。失败报告实际原因，先核实已落盘产物再恢复，不因认证或地址错误重装插件或更换提供商。

原生章节接力按 [workflow](long/native-workflow.md) 运行维护的模板，不另套自定义执行器。模板阶段已经加载 Skill 时只执行当前阶段，不能递归调用 workflow。
