# 长篇开书与规划

用于设定、卷纲、细纲和补纲。用户只要求开书或规划时，完成所需设定与细纲即停；只有明确要求正文才进入 [单章流程](workflow-chapter.md)。当前项目路径和状态先按 [项目与对标](project-context.md) 确认。

## Phase 1：方向

使用用户已经给出的核心想法、读者情绪、平台和篇幅；项目已有 `选题决策.md` 时读取相关结论，不重复市场调研或向父目录搜所有书。没有方向时由 `story` 帮助选题。

对标可选。只在本次明确需要时按 [项目与对标](project-context.md) 识别外部作品与主对标，排除本书自身；无对标按本书读者承诺、因果与阶段目标规划。依赖的分析资料缺失时由 `story-analyze` 补相关部分，不把已有文本接入当成分析修复命令。

## Phase 2：核心设定

先确定一句话梗概、主角目标与能动性、核心阻碍、题材情绪、世界规则及本书要偿还的期待。只补当前规划需要的角色、势力和背景，不能为填模板杜撰用户已确认的事实。

按 [产物模板](artifact-protocols.md) 创建或增量更新 `设定/题材定位.md`、`设定/关系.md`、相关角色与世界观档案；题材卡只提炼本书实际取舍，用户的 `设定/文风.md` 保持权威。复杂世界观或人物关系可按 [原生协作](../delegation.md) 委派独立专家，提供项目路径、具体文件产物、相关约束及资源位置；普通设定由主会话完成，不例行拆成多个代理。

## Phase 3：大纲搭建

按全书阶段 → 卷 → 剧情单元 → 章节细纲组织，模板见 [产物模板](artifact-protocols.md)。先写每阶段/卷要交付的读者情绪、主角目标、起止状态、主要冲突、允许揭示与保留到后期的信息；比例和八节点等方法仅作参考，不要求机械套表。

卷内剧情单元明确主推线、可能同时得到的战果、关键选择与兑现归属，允许多线共同变化。对标只能提供可转换的情绪与功能，不能照搬人物、独特情节或表达；按需使用 [结构方法](outline-structure-theory.md)。

规划完成时用 [读者契约](reader-contract-and-progression.md) 核查主角因果权与结算权、期待债、终局底牌及升级空间。删除主角或题材核心后兑现仍完全相同时，先修正设计；可以没有行动成本，但收益归属和状态变化必须清楚。低压、关系与整理章节按本书需要分配，不设统一占比或连续章数上限。

默认先规划首个剧情单元、首批至多十章细纲；用户给定范围时按范围分批完成。只展开当前可执行部分，不一次填满全书。新书无追踪状态时按 [追踪事务](tracking-transaction.md) 初始化第 0 章。

### 细纲（全书每章）

正式章节每章一个 `大纲/细纲_第NNN章.md`。以下是唯一模板；未知字段明确标注待补充，关键语义未确认前不能写正式正文。五段式和情节点表记录发生什么，正文的组织形态可以重排、合并和交织。

```
## 细纲（第 N 章）

### 第 N 章：{章名}
- 核心事件：{一句话；供日更与导入统一消费}
- 字数目标：{X} 字
- 字数口径：visible_chars_v1
- 阶段位置：{开篇期/发展期/高潮期/收尾期；第X阶段第Y章；本章在阶段内承担什么}
- 单元ID/位置：{卷纲剧情单元ID；单元内第几拍/承担功能}
- 目标情绪：{具体情绪前状态→后状态；本章推进单元情绪引擎的哪一环；不得只写“热血/悲伤”等标签}
- 读者期待：{本章读者等待哪件具体事情发生}
- 主角目标：{主角本章要达成什么}
- 主要阻碍：{谁或什么阻挡目标，怎样施压}
- 关键选择：{主角必须亲自作出的取舍；删掉这个选择会改变什么}
- 代价或后果：{这个取舍付出的成本或造成的具体变化}
- 局部兑现：{本章交付的结果、关系变化或理解，不预支后续真相}
- 章尾问题：{读者下一章还想知道或见证什么}
- 章节定位：{高压/推进/修炼试错/关系回收/低压生活/信息整理；可留空，留空按推进章。见 references/long/outline-structure-theory.md「章节定位与张弛」}
- 本章结构公式：{可选组织方法；按实际事件安排，不要求固定节点数或占比}
- 章首钩子：{具体切入方式；钩子公式仅供参考} — {具体内容；低压/过场章可写“弱钩子/仅情绪钩子，功能是…”}
- 爽点：{本章爽点；低压/修炼/过场章可写“无显性爽点，功能是…”，但仍须给读者一个往下看的理由}
- 本章禁止提前释放：{后续阶段核心真相/底牌/关系结论/终局矛盾；没有就写“无”}
- 契约风险：{契约安全/需补强/契约破坏；检查本章信息边界与主角代理权后填写}

#### 内容概括（五段式）
- 起因：{本章事件为什么发生}
- 发展：{冲突如何推进}
- 转折：{信息/关系/局势哪里改变}
- 高潮：{本章情绪或动作峰值}
- 结尾：{本章最后落在谁的什么动作/画面/台词上——写具体落点，不写"尘埃落定""一切结束"式状态判词}

#### 情节安排（多线）
- 主线推进：{本章对主目标的推进}
- 辅线推进：{可写“无”，不能凭空制造}
- 事件线 / 任务线：{外部事件链}
- 任务卡点（如适用）：{角色要办什么事 → 卡在哪里 → 卡出什么变化 → 删掉后损失 → 收束动作；没有就写“无”，不强补}
- 感情线 / 关系线：{无显性感情线时写“无显性，但关系变化为…”}
- 逻辑线：原因 → 行动 → 结果 → 后果/新问题

#### 人物关系和出场顺序
- 出场顺序：{角色/势力/关键物件按实际出现顺序列出}
- 人物关系变化：{本章前 → 本章后}
- 视角/信息差：{谁知道什么；读者知道什么；主角误判什么}

#### 情节细化
- 情节点序列（逐行填下表；写清动作与叙事功能，不填写逐点字数）：

| # | 情节点（谁做了什么） | 功能标签 | 执行边界 |
|---|---|---|---|
| 1 | {主角在账单上发现4800元转出} | {信息揭示} | {只确认异常，不揭露幕后者} |

  功能标签＝目的词：铺垫/高潮/爽点/打脸/人物塑造/设定，用于判断该点承担什么义务；执行边界写本点不能提前释放或新增什么。点数由语义需要决定，不用 `目标字数 / beat 数`、固定字数档位或历史偏差系数反推。结构预检只判输入是否可安全执行，不宣称细纲一定能撑到目标字数。
- 任务卡点说明：如果某情节点是“办事被卡住”，功能标签必须写清它服务的是信息揭示、关系变化、代价兑现、伏笔推进、选择压力、节奏喘息或钩子承接；删掉无损的卡点不进细纲
- 复沓锚句：{须一字不差进正文的原话（誓言、面板、旧案原话），一行一条并注明落点，如"点3：立此为凭…"；没有写"无"}
- 行动成本（可无）/收益归属：{可无行动成本；若有则写谁付出什么成本；收益归谁、如何可见、是否留下后续账}

#### 结尾设定和钩子
- 结尾设定：{收束落到什么具体动作或画面（不写"就这样……""他终于明白……"式状态判词）；未解决问题；下一章推动力}
- 章尾钩子：{适合本章的承接方式} — {具体内容，期待度：强/中/弱；低压/过场章可弱钩子或留阶段目标；与下一章如何承接}
```


细纲落盘后运行 `node {CLI} outline check --json --workspace {工作区} --book {作品名} --chapter {N}`。失败只修点名字段后再检；检查通过仍由准备执行者核实读者期待、目标、阻碍、选择、后果、兑现和章尾问题具体可执行。不得用占位词、固定字数换算或新增事件凑可执行性。

### 中途补纲

续写请求包含在已确认卷纲内补建本章细纲的准备工作：普通路径由主会话完成，原生 workflow 由 Prepare 子 Agent 完成；除非用户明确要求逐章确认，不因文件尚未存在再次索要创作授权。先定位同章已有文件，兼容不同补零和章名；多个候选先核实，不另建一份。新章无正文且无细纲时，只读取当前卷/单元、续写状态卡、上一章和必要设定，按上方模板创建 `大纲/细纲_第NNN章.md`；`大纲/` 缺失时在已核实的工程内创建。材料足够即写入，不重复盘点依赖或通读历史。

把现有卷纲目标、当前事实和停笔边界展开为本章事件与场景计划，不重新要求用户决定常规场景组织。关键依据缺失、材料冲突或需要改变已确认主线、角色关系和信息释放时，列出具体裁定问题后停止依赖写作。已有正文却丢失细纲时先找回原批准版本，不从正文反推一份细纲以通过检查；已有细纲不因重新运行而覆盖。用户明确要求补未来单元时，按其范围分批完成。

细纲写入后用上方命令检查并核实场景计划，通过后才把真实路径交给写手。补纲不推进追踪；原生 workflow 的 Prepare 同时交回细纲哈希、场景计划及复核后的追踪修订号。已有单元的分析结论可复用，不每章重新召回整本对标。未来伏笔和揭示计划留大纲，实际发生后再由逐章事务进入追踪。完成后报告文件与就绪范围，按请求停在规划或进入正文。
