# 用户请求的朱雀检测

只有用户明确要求朱雀检测、过朱雀或同义任务时执行；普通润色和去 AI 味不发送原文。只要求检测时保留正文，需修改时确认已在当前请求范围内。

DSH 内使用 `story_zhuque`，凭据由工具注入同一个 CLI，不读取凭据仓库，不将密钥放入参数或日志。示例：

```json
{
  "book": "神机诸天录",
  "file": "正文/第012章.md",
  "out": ".story-polish/第012章/R0.json",
  "target": 0.5,
  "max_chars": 20000
}
```

工作区来自 Session；book 是直接子目录作品名，file 和 out 都归本书。异步调用使用工具提供的 job 查询/取消并等待真实终态，不能把任务启动当成检测完成。工具不可用时报告缺口，不通过 shell 自行读取 DSH 密钥。

先按 [结果解释](zhuque-detect.md) 核实服务响应与实际覆盖。低分、未执行和失败分别报告；分数不认证作者身份，也不是文学验收。若请求包含润色，根据具体段落问题在原文边界内修改，保留剧情、人物、伏笔和字数约束，不按段落得分强删或扩写。

已有有效报告和未变化正文可复用。仅在用户要求复测或本次任务需要验证改稿时再次调用；检测请求可能产生费用，不为追分无限循环。报告放本书 `.story-polish/`，不写入故事追踪。
