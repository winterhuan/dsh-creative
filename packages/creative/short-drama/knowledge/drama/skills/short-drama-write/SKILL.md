# 短剧剧本

把用户要求的单集或段落写入 `剧集/<EP>/剧本.md`，保留已确认事实与作者语言。只有想法时先在当前上下文形成最小目标、阻力、当集兑现与退出状态；不为流程建立额外节拍表、录音表或审批文件。

默认只读本技能与直接输入。格式不明时读 `references/write/screenplay-format.md`；制作稿方言读 `references/write/production-format-dialect.md`，均通过 DSH 原生 `read` 从资源根解析。

1. 确定本集观看承诺、人物要什么、阻力在哪里，以及最终改变什么。
2. 按“原因—行动—结果”组织场景，把动作、对白、声音与画面文字写进同一剧本。每场有可感知的变化，事务性角色不强加秘密或人物弧。
3. 输入明确给出艰难选择、关键证据、有限次数或精确死线时，读 `references/write/script-craft.md` 对应节并核对它确实改变行动；普通决定和模糊时间压力不升级为机关。
4. 交稿前核对事实、连续性、可表演性、题材语气与承诺兑现；去除无作用的解释、标签和重复收尾。用户要求整集就完成整集，局部修订保留其他内容。

标题使用 `# EP001 集名`、场景 `## EP001-SC001 内 · 地点 · 时间/天气`，对白使用 `角色（表演提示）：台词`，生产标签使用 `[VO]`、`[OS]`、`[SFX]`、`[画面文字]`、`[连续性]`、`[转场]`。稳定场景 ID 不随改名更换。

明确给定目标时长时按真实朗读、动作与停顿压稿；不以统一字数或节拍数替代判断。要求机器时长估算时读 `references/write/workflow.md` 的估算步骤；估算不是质量门禁。

只有遇到相应问题才读 `references/write/dialogue-craft.md`（对白）、`scene-sound-dramaturgy.md`（声音）、`substitutable-realization.md`（可拍替代）；后两个文件也在 `references/write/`。跨上下文交接使用 `references/write/scene-handoff-capsule.md`，不额外落盘。

剧本足以传达承诺、人物行动与本集结束状态即交付。审查、视觉方案与媒体生产只在请求范围内开始；本技能不把自检当独立终审。
