# Novel workbench: the existing story plugin

English | [中文](2026-10-04-novel-studio-plan.zh.md)

## Summary

The workbench stays on `@winterhuan/dsh-story`. Directories, write hooks, and the chapter transaction stay as they are. This pass changes three things: long fiction reads the shared analysis library directly, the author sees the files that will be read before prose is written, and the Zhuque key moves from the shared production settings onto the story settings page.

## Changes from the current plugin

When long fiction cites an analysis, `设定/题材定位.md` records only `拆文库/{书名}/`, and writing reads that shared tree. An existing `对标/` directory can still be opened in the workbench. New citations are not copied into it. A book's own analysis cannot be registered as its own comparison.

Preparation lists `追踪/上下文.md`, the character, foreshadowing, timeline, outline, previous-chapter, and analysis pages actually read, plus the revision returned by `tracking_commit.py check`. The author sees that list before `正文/` is written. The list is not saved as a file and does not replace the JSON.

The Zhuque key stays in the story plugin's `story` settings namespace. `story_zhuque` reads that namespace. The default credential reference remains `MAKERS_API_KEY`, and the key still goes to the credentials store. Short drama, recap, and the aggregate keep the six providers in `creative-produce`. `creative_produce_run` in the aggregate no longer carries `story-zhuque`.

## Boundaries that stay

Long-fiction directories are `正文`, `大纲`, `设定`, `追踪`, `对标`, and `参考资料`. Short-fiction files are `正文.md`, `设定.md`, and `小节大纲.md`. `拆文库` sits on the workspace and is shared by books. `长篇/` and `短篇/` are only containers. The workbench lists those directories and short-fiction files.

When a long fiction already has `追踪/_tracking-state.json`, a chapter write without the matching outline is rejected. After a successful chapter write, the assigned submitter rechecks, reviews, and updates that JSON through the chapter transaction. Writers do not edit tracking. Derived views are generated by the transaction. Short fiction `正文.md` skips this check.

The chapter transaction uses hashes and `expected_state_revision`. Author memory lives in the workspace `.story/作者记忆/` and records style preferences only. Unsaved edits in the session are the workbench buffer, not a directory of the book.

## One book

```text
工作区/
├── .story/作者记忆/
├── 拆文库/{书名}/
└── {长篇书名}/
    ├── 正文/第NNN章_章名.md
    ├── 大纲/大纲.md
    ├── 大纲/卷纲_第X卷.md
    ├── 大纲/细纲_第NNN章.md
    ├── 设定/
    ├── 追踪/_tracking-state.json
    ├── 追踪/上下文.md
    ├── 追踪/角色状态/{角色名}.md
    ├── 追踪/伏笔.md
    ├── 追踪/时间线/作者真相.md
    ├── 追踪/时间线/读者已知.md
    ├── 追踪/逐章记录/第NNN章.md
    ├── 对标/{书名}/
    └── 参考资料/
```

`设定/` holds confirmed characters, world, and voice. `大纲/` is the plan that has not happened. `正文/` is the story already written. `追踪/_tracking-state.json` is the committed chapter facts; the Markdown beside it is generated by `tracking_commit.py` and is not parsed back. Author truth and reader-known are two derived timeline views.

Short fiction is the sibling files `设定.md`, `小节大纲.md`, and `正文.md`, without `追踪/`. The skill's `草稿/` holds exploratory prose and does not advance tracking. Unsaved edits stay in the current Session buffer.

## Reading existing files

The existing Markdown is the readable layer: `设定/`, `大纲/`, derived pages under `追踪/`, and `拆文库/`. A query reads `追踪/上下文.md` first, then one character state, one foreshadowing row, author truth or reader-known, this chapter's outline, and the previous chapter. The full `_tracking-state.json` does not enter the prose prompt.

Ingest is the existing `chapter commit`. Derived pages update together when the transaction succeeds. The check remains `tracking_commit.py check`: derived pages must match the JSON byte for byte. Comparison material is read from the pages this step needs inside `拆文库/{书名}/`. No new `index.md` or `log.md` is added.

## One writing pass

Long fiction still prepares, writes, runs `chapter check`, reviews, revises at most twice, and runs `chapter commit`. Consecutive chapters are called serially by the parent session, and the next chapter starts only after the previous commit is verified. Short fiction still follows the short-fiction writing flow. Design fields must pass before prose is written.

Discussion does not change tracking. Review does not change prose. Exploratory text may go in the skill's `草稿/`. After formal prose is written to `正文/`, the hook's recheck and the chapter transaction still apply.

## Workbench

The workbench keeps showing the files in the directories above, with a Session buffer and versioned saves. An external change keeps edits that have not been saved. There is no task drawer and no second set of facts.
