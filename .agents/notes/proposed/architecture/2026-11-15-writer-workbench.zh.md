# Agent Note: Writer 小说创作工作台

Status: proposed

[English](2026-11-15-writer-workbench.md) | 中文

## 问题

Writer 已提供 oh-story 流程、版本守卫编辑、草稿恢复、章节检查与版本化审稿，但依附会话的右侧栏让作者先理解文件，才能理解作品。完整工作台需要更大的写作空间和明确的作品归属，同时保留既有书稿与原生对话。

## 提案

升级现有 `@winterhuan/dsh-writer` 包，保留预设 ID `writer`。使用官方主面板、侧栏入口和嵌入式原生对话。首版覆盖已有长短篇作品的规划、写作与审稿。研究视图和可选封面生成保持可达，不作为写作前置条件。

本提案扩展[写作模式决策](../../implemented/feature/2026-10-31-writer-preset.zh.md)：技能优先级、版本守卫保存与角色派发仍是约束；侧栏呈现方式拟由工作台接替。[浏览器决策](../../implemented/architecture/2026-11-07-writer-box-ego.zh.md)继续适用。这些记录保持有效，尚未实现的提案不替代已实施决策。

### 导航与首次进入

顶层使用三个入口：作品、拆文库、扫榜；设置作为辅助操作。默认打开作品页；同一浏览器再次进入时恢复上次有效作品和文稿，不发送提示词。作品缺失时保留登记并提供定位操作，不静默重建目录。

作品页使用紧凑卡片或同等信息密度的列表，显示书名、长短篇、目录提示和有记录的进度。进度缺失显示未知，区分正文保存与章节提交。「继续创作」打开上次文稿和关联对话。不虚构封面、文学评分、连续打卡或由不完整记录推算的完成百分比。

空作品页提供「打开已有作品」和「新建作品」。打开时明确选择已登记工作区和书目录；发现过程提供候选，不自动登记所有扫描目录。新建只收集书名、长短篇与目标位置，然后提供规划请求。校验名称，拒绝覆盖已有目标路径。创建工作区或目录需要使用原生控制器与文件权限的小型 Host 操作；当前仅替换文件的保存接口不能直接创建工程。

### 写作布局

作品页与书内工作区分开。进入作品后，紧凑顶栏包含返回作品、书名和当前文稿。保存状态靠近文稿，对话操作靠近助手，避免全局导航、作品标签和编辑标签叠成三行常驻工具栏。

以下线框表达信息归属，不代表最终样式。审稿区域切换到正文区或在正文下方展开，不形成第四个常驻栏。

```text
┌───────────────────────────────────────────────────────────────────────┐
│ Works ←   Book title           Current document          View options │
├──────────────┬───────────────────────────────┬────────────────────────┤
│ Overview     │ Chapter title    Save state   │ Writing assistant      │
│ Chapters     │ Edit / Preview / Changes      │ Current conversation ▾ │
│ Outline      │                               │                        │
│ Settings     │         Manuscript            │ Native messages,       │
│ Tracking     │                               │ tools and approvals    │
│ Files        │                               │                        │
│              ├───────────────────────────────┤ Native input           │
│              │ Checks / Review (expandable)  │                        │
└──────────────┴───────────────────────────────┴────────────────────────┘
```

书内导航包含概览、章节、大纲、设定、追踪和作品文件。设定指故事设定，不是应用设置；双语文案须明确区别。短篇显示正文与小节大纲，不展示空的章节／卷层级。作品文件保留受支持文本和结构化记录入口。选中文稿统一拥有编辑、预览、差异与恢复状态。

布局试验从 220 px 导航栏、约 380 px 可调整助手和并排时至少 520 px 正文区开始。测量扣除 DSH 界面后的面板容器，不按浏览器总宽度判断。空间不足时先收起导航，再切换内容／助手，不强行挤压两者。这些数值是试验起点，不是固定验收断点。

进入作品时，只要容器空间足够，默认展开原生助手，与正文并排显示；再次打开作品时，不将上次收起状态恢复为默认布局。作者可手动收起助手或进入专注模式；受限宽度下使用内容／助手切换。专注模式收起导航与助手，保留文稿标题、保存状态和退出入口。各区域独立滚动。切换视图模式保留选中对象、原生待发输入、附件和正文草稿。调整宽度与焦点返回应支持键盘操作。

### 视觉设计

背景、边框、字体、菜单、对话框和 Toast 使用既有 DSH 主题与组件。参考 Media Desk 的面板组织和原生聊天集成，沿用 Writer 克制的文稿呈现：安静的底色、明确对齐、轻量分隔，每个区域只有一个主要操作。首版不需要装饰玻璃、动态背景和大幅封面墙。

控件沿用既有紧凑字号，功能样式字重最高 500。正文使用独立、舒适的阅读字号与受限行宽，并以中文长段落和中英混排验证。颜色只作辅助：已保存、未保存、已过期、失败和运行中同时提供文字或图标。两种主题都验证对比度。

采用共享图标库，为含义不明的图标操作提供提示。菜单不受容器裁剪，适配窗口边缘，并可通过外部点击或 Escape 关闭。局部处理 macOS 标题栏避让，验证 Windows 和触摸布局，不修改全局主题变量。操作不能仅在悬停时可见。

### 规划、写作与审稿

概览说明已有进度、未完成材料和下一步可用操作。主要操作依据记录决定：存在未完成材料时继续本章，否则准备下一已知章节或规划步骤的请求。不从空工程、规划确认或选中细纲推断正文授权。

章节行显示章号、标题以及分别有证据的正文／检查／审稿状态。选中打开正文，相关细纲、检查与审稿无需浏览原始 JSON 即可到达。记录无效时指出问题记录与恢复操作；记录缺失表示未检查或未知，绝不表示通过。章节提交继续使用现有 oh-story 流程。

审稿在正文附近展开，显示严重度、引文、解释和修改建议。只有当前版本仍匹配时才定位引文，否则展示审稿版本并标记过期。差异与已记录审稿正文比较。处理意见通过请求调用现有校验记录器，不以本地勾选作为决定。请求失败或中断不能显示已接受处理结果。

上下文操作在原生输入中准备明确任务，保留已有草稿与附件。请求包含作品、章节／文稿、操作和停点。选段讨论附带来源版本，并标明未保存文字。实际修改前由执行路径重新读取或校验来源；仅在引用中附版本不能提供并发保护。作者发送前不发起模型请求。

### 对话与上下文恢复

每本书有默认继续的原生对话，并可保留此前阶段的对话。使用原生会话／工作区控制器创建或关联真实 Session。打开作品与发送输入分开。关联已有会话前核验 home、工作区、预设和作品归属；标题相同不足以确定关联。两本书不能意外继承同一活动关联。

保留 Writer 原生自动压缩、工具结果修剪与手动压缩命令。不显示虚构的上下文百分比，也不声称压缩保留全部事实。原生压缩反馈继续由原生对话呈现。只有受支持运行时提供数据时，才增加工作台压力指示。

「开启新阶段对话」是明确操作，并保留旧 Session。有任务运行时提供等待或使用原生停止的选择，等待任务停稳再更换关联。释放面板不停止 Agent。旧对话仍可从原生工作区访问。

新阶段写作前从已提交追踪记录恢复当前章与修订，使用既有派生上下文卡，再按技能要求读取当前细纲、相关设定、作者约束与邻近正文。不在每轮加载整本书或完整追踪 JSON。状态缺失或矛盾须在写作前明确。关键作者决定通过现有流程记录，不能只留在聊天摘要。

### 文件、草稿与持久化

书内文件继续作为内容依据，包括现有中文目录与 `.story` 记录。不迁入 Wiki Notes，不新增第二份可编辑正文存储。Host 仅登记规范化的工作区／书目录与真实对话关联，并按 DSH home 隔离；浏览器偏好保存布局与最近选择。书名不是身份。目录移动需要明确重新定位并核验关联。

复用 `useWriterDocument`、草稿存储、换行处理、版本守卫保存、目录发现与审稿解析。将编辑状态从当前按会话挂载的组件中提取前先核对归属。同一浏览器运行时由主面板独占编辑，旧侧栏将当前文件定位到主面板。保留既有恢复键，或提供经过测试的明确导入。

外部修改刷新无本地改动的文稿；存在本地改动时保留草稿，提供对比／重读，不覆盖任一版本。迟到读取与保存不能更新另一文稿、作品或对话。开启新阶段不得丢弃未保存正文。保留既有写权限检查，作品登记不授予文件访问权限。

### 加载、失败与空状态

列表加载使用骨架，首次文稿加载使用居中转圈。刷新期间保留已有内容。查询失败在附近提供重试；临时操作结果使用全局 Toast。保存冲突和浏览器恢复不可用在编辑器旁持续显示，直到解决。错误使用简短的双语文案。

工作区缺失、预设不符或 Session 不可用时提供修复入口，不静默另建会话。文件权限允许时继续提供作品浏览。忙碌按钮说明当前操作；停止或失败的模型轮次不代表章节完成或审稿已保存。

### 实现职责

实现留在现有 Writer 包内。按职责拆出主面板外壳、作品页、书内导航、文稿视图与原生助手适配；从 `desk.tsx` 提取文稿控件，复用既有发现、文稿、审稿与差异模块。不新增通用工作台框架或第二套写作运行时。

| 职责 | 现有归属 | 必要改动 |
| --- | --- | --- |
| 入口与导航 | `client/index.ts`、`sidebar.tsx`、`mode.ts` | 注册官方主面板与始终可见的工作台入口；关联编辑／对话继续核验 preset。 |
| 作品发现 | `library.ts`、`search.ts` | 仅扫描明确选定的原生工作区，选择候选后才登记作品。 |
| 文稿编辑 | `desk.tsx`、`use-writer-document.ts`、`draft-storage.ts` | 将文稿生命周期与当前 Session 分开，提取编辑控件并保留恢复键。 |
| 检查与审稿 | `BookPanel.tsx`、`book-status.ts`、`RevisionDiff.tsx` | 在选中章节附近呈现既有校验记录，保留指纹失效判断。 |
| 文件授权与保存 | `read.ts`、`save.ts`、`write-route.ts` | 继续使用原生授权读取和预期版本保存，会话变化后重新核验。 |
| 作品与对话登记 | 新增小型 Host 服务 | 保存稳定作品 ID、原生工作区 ID、相对书路径和阶段 Session 关联，以串行原子更新持久化。 |
| 原生助手 | 新增使用官方工厂的 Client 适配 | 明确 retain 作品关联的 Session，在该作用域内呈现原生输入／历史／批准。 |
| 技能与凭据 | 现有 preset、设置与 `writer-agent.ts` | 保持现有归属，仅按作品选择需要补充任务上下文。 |

### 工作区身份与文稿生命周期

区分原生工作区根与书目录。接管已有 Session 时保留原工作区根，将书登记为根下经过校验的相对路径，兼容书就在根目录的情况；新阶段 Session 沿用该工作区。这样保留工作区指令、项目技能发现和当前 `[cwd, relativePath]` 浏览器恢复键，不静默将 Session 根改为书目录。

多本书共用工作区时，所选书必须成为明确任务上下文。用户浏览另一书时不改写工作区级 `.active-book`。支持书路径的技能与命令显式传入路径，每个快捷操作在开放前核对。仍依赖工作区级当前书偏好的流程，需要串行执行或明确选择，不能让并行对话静默互相切换。

文稿控制器按工作区和相对文件身份归属，独立于助手是否显示及阶段 Session ID。切换阶段对话时保持控制器存活，暂停保存、等待正在进行的保存结算，再通过新授权 Session 重读并核验基线后启用保存。当前代码打开另一文件会关闭并清除恢复副本，因此切书前应提供保存、保留草稿或取消。保留草稿必须持久成功后才释放控制器；恢复存储失败时提供下载或停留在原文稿，不能将恢复写入失败当成切换成功。

首版将旧可编辑侧栏替换为「打开工作台」，携带当前 Session／作品／文件定位。这样单个浏览器运行时由主面板独占编辑，无需新增全局编辑服务。多个浏览器标签页仍使用既有恢复副本冲突检查和文件版本。

### 原生绑定与操作状态

全局工作台不能继承其他位置当前选中的任意原生 Session。参照 Media Desk，为对话子槽提供由所选作品关联确定的严格 Session 作用域，使用官方工厂并配对 retain／release；隐藏助手布局时保留原生输入状态。按实际调用补充对应 DSH 包声明和 Remote 类型导入。

作品可用性、对话绑定与文稿状态分别管理。作品状态为可用、缺失或待重新定位；绑定为未关联、创建中、就绪或待修复；文稿包含加载、干净、已修改、保存中、冲突与失败。对话出错不清空已打开正文，文件出错不清空原生聊天。操作显示进行状态，仅禁用相互冲突的动作。

按书串行更改关联，调用原生控制器前持久创建意图，取得真实 Session ID 后立即记录并保留部分创建证据。刷新或重复点击不能再次创建 Session。崩溃后创建结果未知时，通过受支持的原生证据核对或显示修复，不自动重复。登记元数据只保存引用，不复制 Session 日志或书稿。

快捷键明确区分编辑区与助手。当前 `isChatComposerTarget` 将 Writer 工作台后代排除在聊天输入之外，嵌入聊天后这一判断失效。保存与搜索限定于编辑／导航区域，保留原生聊天快捷键，并测试关闭菜单、定位审稿和窄屏切换后的焦点。

### 实施顺序

1. 布局试验：在 DSH `0.2.2-rc.1` 注册主面板和官方对话 slot，使用现有编辑器展示已有书稿。先验证容器宽度、原生输入、选择、草稿保留与两种主题，再扩展功能。

2. 作品打开：实现明确登记、经过校验的 Session 关联、长短篇导航和旧侧栏跳转。保持单一文稿编辑归属，验证旧草稿及 Host／浏览器重启后恢复。

3. 写作闭环：增加有记录依据的概览、章节选择、大纲／设定导航、审稿浏览和原生草稿操作。使用现有技能，为一部长篇与一篇短篇走通规划到修订。

4. 完善：整理拆文与扫榜视图、加入安全工程初始化、完成新阶段恢复与压缩检查，再更新双语文档并构建固定 Git 安装包。付费封面仍需明确请求。

## 考虑过的替代方案

**只扩大右侧栏。** 能保留当前注册方式，但仍与原生对话争抢正文宽度，作品流程仍隐藏在会话导航之后。

**完整复制 Media Desk 实现。** 面板和聊天集成值得参考，但 Notes 迁移、成稿接受与发布模型会增加无关存储和流程职责。使用 DSH 公共组件，首版不新增共享工作台框架。

**永远使用同一对话，或每章创建新对话。** 前者累积混杂决定并过度依赖摘要，后者丢失有用的近期连续性。默认继续的会话配合明确阶段切换，兼顾连续性和有范围的恢复。

**新建写作引擎或嵌入 oh-story Dashboard。** 两者都会替换现有归属，而非呈现已有能力。保留原生对话、当前技能与经过校验的书内记录。自动发布、定时写作和关系图编辑器不纳入首版。

## 验收标准

- 真实 DSH 设计评审：在宽屏、受限宽度和触摸尺寸下，以两种主题检查作品页、长篇编辑、短篇编辑、过期审稿、文件冲突与新阶段对话。正文易读、控件可达，不出现第四栏或被裁剪浮层。

- 内容保护：目录发现、登记、切换视图和更换对话保持已有文件字节不变；保存只修改选中文稿。读取／保存失败、外部编辑、快速切书与重启均保留未保存草稿，覆盖迟到回包和旧恢复格式。

- 流程：仅规划时不写正文，写指定章不扩大范围，查看有效与过期的检查／审稿，并通过现有校验流程记录审稿决定。文件存在不证明已提交进度。

- 原生集成：布局切换保留待发文字与附件；工作台与原生工作区打开同一真实 Session；关闭视图不停止任务；验证停止、失败、重新关联和重启，不重复提交提示词。

- 上下文恢复：在隔离运行时实际触发压缩，检查持久压缩事件并继续写章，再开启新阶段恢复章号／修订、相关角色状态和已记录作者约束。受控 fixture 验证机制，真实模型运行检查恢复可用性，不认证文学质量。

- 交付：运行 Writer 类型检查、构建与测试、相关文案／UI 门禁及文档检查。在隔离开发 profile 验证构建包，重启 Host 并硬刷新浏览器。本规划不声称这些产品检查已执行。

## 风险

原生主面板 Session 作用域、控制器 API 与文稿归属必须通过布局试验证明；Media Desk 代码不能证明 Writer 集成。提取较大的侧栏组件可能重复副作用、破坏草稿归属。复用已有小模块，只修改主面板所需部分。

压缩可能遗漏创作细节，单个超大输入仍可能超出模型容量。文件恢复依赖作者和技能记录关键决定。既有技能副本可能覆盖新版包内行为；保留来源诊断与明确同步，不静默替换项目定制。
