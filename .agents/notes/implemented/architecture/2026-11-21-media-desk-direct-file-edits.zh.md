# Agent Note: Media Desk 日常改稿使用原生文件工具

Status: implemented

[English](2026-11-21-media-desk-direct-file-edits.md) | 中文

## Problem

日常改稿需要助手把内容编码为业务操作 JSON 字符串，并提供版本映射和各操作所需字段。参数无效会拒绝保存，创作提示又禁止原生文件写入。Notes 已支持外部编辑，该限制却使 Agent 无法像其他编辑器一样使用同一份可编辑文件。

## Decision

Agent 通过原生文件工具读取和修改已登记 Notes 文件。只读 Media Desk 校验器使用现有格式与身份解析器检查已保存字节。校验直接读取登记引用，因为 Store 读取还会导入外部编辑、写入快照并更新导航。校验不保存文件，不修改索引、历史、回执或撤销记录，也不会自行修复文件。

普通工作台刷新通过现有 Notes 投影流程导入有效文件变更、更新内容版本并保留此前快照。直接编辑立即生效，停止或失败的原生轮次不会回滚文件。这类编辑没有业务保存回执或工作台撤销条目。原生文件权限继续生效；创作指令要求遵守作品绑定、读取当前文件、保留身份／语言元数据，并在完成前修复格式。

该方式替代[原生创作](2026-11-11-media-desk-native-agents.zh.md)中的日常文字编辑路径。[原生接受](2026-11-12-media-desk-native-acceptance.zh.md)仍管理结构化成稿候选、持久阶段完成、媒体、工作流状态与恢复。结构化阶段提交候选，不直接修改其当前 Notes 文件；协调状态更新仍使用 Host 保存日志。既有业务操作继续兼容保留的调用方。

## Alternatives considered

**继续让 JSON 业务工具成为唯一文件写入者。**每次编辑都可保留业务回执，但普通改稿需要反复转换参数并提交版本映射。原生文件工具已经提供可编辑文件流程。

**让校验同时保存或导入内容。**检查会因此修改快照、Store 或索引，并可能在部分保存后失败。Agent 管理文件写入，普通刷新管理导入，校验只报告当前文件格式。

## Consequences

日常写作使用原生文件差异和权限流程。无效字节在修复前仍留在磁盘上，格式通过不代表事实正确、阶段接受或业务事务完成。工作台保存与结构化阶段保留既有冲突及恢复行为。

包内直接文件测试执行真实原生 read/edit/write 调用、无效格式修复，以及工作台版本／历史／索引刷新。独立文件系统比较证明校验不改变文件内容、修改时间或 inode，涵盖材料与偏好。确定性证据不包含真实模型的工具选择或写作质量。
