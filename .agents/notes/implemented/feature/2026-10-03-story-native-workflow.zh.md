# Agent Note: 通过原生 workflow 工具完成小说章节

Status: implemented

[English](2026-10-03-story-native-workflow.md) | 中文

## Problem

正式章节需要准备、写作、检查、审稿、修订和追踪事务。Skill 指令组织这些步骤，但提交脚本不核实实质审稿是否发生。反复临时委派让遗漏交接和失败处理更难检查。另建执行引擎、专家包装层或进度数据库会重复 DSH 的能力。

## Decision

小说包为已有原生 `workflow` 工具提供[单章模板](../../../../packages/creative/story/knowledge/story/skills/story-write/workflows/chapter.js)和按需加载的[调用说明](../../../../packages/creative/story/knowledge/story/skills/story-write/references/long/native-workflow.md)。公开入口仍是六个 Skill。`story-write` 只在用户明确选择或已有持续偏好时进入此路径，普通写作与审稿保留直接执行方式。

父会话提供工程、章号与当前用户约束，可附已知上下文，读取调用说明和模板后，将原样 JavaScript 正文传给顶层原生工具调用。DSH 负责执行、子会话、取消、后台作业与运行展示。不增加小说执行器、直接引擎调用方、自建面板或第二套作业登记。缺少能力时报告具体诊断，不静默换成另一种模式。

每次调用处理一章正式长篇新章及其未提交稿的局部修订。Prepare 定位实际文件、核对追踪、复用可用细纲或在已确认规划内补建缺失细纲，并生成有长度上限的场景计划。缺失事实或规划冲突会停止依赖工作。检查后的细纲哈希和追踪修订号随实际路径、场景计划交接；调用方显式提供的路径和修订号仍作为约束。写手读取 Role、Skill 与准备好的来源，在范围内写作并运行现有检查。细纲或修订号变化时停止交接给审稿者。独立审稿者读取审稿 Skill 和实际文件。初稿后最多两轮修订，每轮后重新审稿，最后由提交子会话构造并验证带保护的 append 事务。连续续写串行调用模板，验证提交后才推进；原生 `pipeline` 会并发处理不同条目，不适合连续章。

## Review routing and source identity

workflow 审稿者返回 `recommendation: ready | revise | needs_input` 和可读的 `review`。`ready` 是该模板进入提交阶段的条件，但只是可能出错的模型建议，不是文学质量的客观证明。响应没有分数、引句配额或模型元数据。普通 `story-review` 保持自然语言，不增加审稿记录、追踪 schema 或历史数据迁移；原生 Session 历史正常保留响应。

`chapter check` 返回受检字节计算出的正文、细纲 SHA-256 哈希，绑定追踪修订号。来源采集和整次检查都会拒绝观察到的文件或状态变化。审稿者在阅读前后比较轻量来源身份。已有事务可选接收 `expected_body_sha256`、`expected_outline_sha256`；提交在项目写锁内校验它们及 `expected_state_revision`，写入前再次检查来源。普通 `storyctl` 路径也将本次新检查绑定到事务；不带可选保护的直接事务仍受支持。

正文或细纲字节变化后需要重检重评审，追踪变化后需要重载事实并重构任务或事务，不能静默更新预期值。提交子会话验证实际章节进度、持久字数记录及来源哈希。锁不跨越模型等待，这些检查也不承诺隔离任意外部文件系统写入者。

欠长稿不填充。超长稿在本次调用与恢复工作中合计最多压缩一次。自然长度待接受时交回作者；明确接受绑定准确的正文和细纲哈希，任一变化后失效。审稿者的 `ready` 不能提供该授权。

## Outcomes and recovery

`committed` 要求提交成功且产物验证完成。`already_committed` 只验证已有结果，不重写或重复提交。`needs_input`、`revision_limit` 保留草稿和相关问题；带这些状态的原生运行完成不代表章节已提交。子会话 null、无效响应和检查失败都会停止后续工作。提交结果不确定时返回 `uncertain`，重试前先核对产物。

取消保留真实文件和已完成事务，不回滚。新调用重检重评审现有未提交稿，不恢复 JavaScript 栈。用户改变范围时须取消、核对产物，再带新输入发起调用；父会话消息不会自动更新运行中的子任务。显式后台执行复用原生作业，下一章仍须等待终态结果。

## Alternatives considered

**仅靠自然语言组织。** 小任务仍适用，但反复生产章节时没有维护好的阶段跳转和修订上限。

**新增小说工具、Role 执行器或直接调用 workflow 引擎。** 这些方式增加一层维护责任，还可能绕过原生工具记录和后台整合。只有确实要求强制使用不可变模板时，才需要重新考虑 Host 入口。

**每次提交都强制审稿证明。** 固定证据数量和模型元数据不能证实文学质量。workflow 内部的分支响应足以完成交接，无需恢复持久质量证明或改变普通审稿。

**只在父会话准备。** 这让缺细纲和场景规划留在选定 workflow 之外，并在入口重复前置工作。原生 Prepare 阶段让准备过程可见，将已检查输入交给写手；只有实际缺失的决定才交回作者。

**所有审稿都交回父会话。** 这能避免结构化交接，却中断了选定的完整工作流。模板只将缺失事实、作者必须裁定的事项和用尽修订次数的问题升级，其余授权范围内的局部工作在内部完成。

**并发连续章或修到批准为止。** 依赖前章的章节可能读到过期事实，无限改写也可能反复震荡或仅为满足审稿者而改变故事。实现串行处理章节，并在修订上限处保留未解决问题。

## Consequences

作者获得可检查的阶段责任和有上限的停止行为。结构化校验只能检查字段与跳转；不同会话意味着不同执行者，不保证不同模型或相互独立的偏差。审稿仍可能错误。原样复用模板及审稿只读是指令要求，不是 Host 强制机制或逐审稿者工具 ACL。

目录保持不变，模板与说明只在选用时加载。调用说明由父会话读取，子会话直接接收阶段职责并加载选定参考。Role 提供专业方法，写入 hook 将追踪交给指定提交者，详见[规则归属决策](../simplification/2026-10-03-story-rule-ownership.zh.md)。它们的源码及独立子会话读取会增加 token 与模型调用。[包说明](../../../../packages/creative/story/README.zh.md#model-experience)记录了静态 token 估算及限制。脚本化模型测试不能得出端到端效率或文学质量提升的结论。

影响后续章节的已提交章修订、短篇、接入、全书分析、Team 编排、新按钮、版本历史及自动崩溃续跑均不在此模板范围内。不增加日更脚本，父会话串行复用单章资源。

[原生专家决策](2026-10-01-creative-role-agents.zh.md)保持有效，仅在 workflow 结构化路由上增加这一有限例外。[六技能决策](../simplification/2026-09-30-story-skills-native-resources.zh.md)、[读者价值决策](2026-09-22-novel-reader-value-generation.zh.md)及[独立领域决策](../architecture/2026-09-30-creative-four-domain-plugins.zh.md)继续约束各自其余职责，没有完整失效或需要归档的 active 三件套。

## Testing

Python 回归拒绝过期字节、追踪修订号及检查和事务校验期间的确定性改动，并保留直接提交和历史记录。模板测试覆盖准备交接、可选调用约束、细纲变化、路由、两轮上限、长度裁定、无效/null 响应、验证身份和恢复结果。原生组合测试使用真实模型循环、顶层工具运行时、worker、独立子会话、带写入 hook 的原生文件读写、检查、带保护的提交及持久生命周期事件，并验证 Prepare 内补建细纲、复用已有细纲、缺失规划事实、无原批准细纲时保留正文、待裁定返回、无效结构化审稿和取消清理。脚本化模型验证执行，不评价文学判断。

仓库 typecheck、build、全量测试及文档检查覆盖交付的资源与规则。隔离 DSH 验证及打包资源检查记录在 [HANDOFF.md](../../../../HANDOFF.md)，验证不涉及用户 profile 或付费模型。
