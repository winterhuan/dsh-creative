# Agent Note: 游戏 QA 必须有可认证的浏览器证据

Status: implemented

[English](2026-09-27-novel-to-game-playability-evidence.md) | 中文

## 问题

手写 QA 记录不能证明当前构建能启动、绘制、响应输入或到达结局。纯文本浏览器也不能提供 Canvas/WebGL 证据。每次改编都重写状态、存档和重开，会在规则形成前消耗工作量。

## 决策

固定的 `game-qa` 生产入口用独立临时 profile 启动 Chrome。服务端与 Studio 共用 CSP 来源和带 Session 前缀的资源路径。驱动重放固定的 `qa/plan.json`，读取统一状态 hook，截图并比较画面，检查设计结局和重开。缺失控件、运行错误和 CSP 错误会失败；机械阻断始终只有六项。

Host 只向该入口提供进程私有签名密钥。驱动对包含命令、退出码、文件哈希和截图的完整记录签名。Host 认证记录并复核工作区内的证据与构建文件后，才在预览旁显示通过。导入或改写的记录、变化后的构建及 Host 重启都要求重跑。直接 shell 运行可诊断，但不能生成 Host 认可的 PASS。

`game-build/templates/create_game.py` 提供叙事、回合制和 Canvas 起点，已有确定性规则、事件、保存/读取、重开、主题变量及 QA hook。默认美术标准采用本地 SVG、CSS 和 Canvas；需要时使用本地合成音效。美术方向必须与实装资产一致，此方案不依赖新增付费游戏媒体入口。

驱动对 default、greedy、random 各跑五个 seed，记录经验胜率和未观察到的结局。Skill 把限时盲玩请求交给独立代理，不附设计或代码，保留提示、操作和观察。缺少浏览器或子代理能力时明确记录限制。这些报告帮助设计判断，不构成第七项机械检查。

游戏 bridge 提供导出器、谱系、来源索引和模板的绝对路径。接入可消费小说导出包并检查索引覆盖；选段分析记录范围，不声称覆盖全书。构建使用本地相对资源，因为 Studio 禁止外部脚本、字体和网络访问。

## 考虑过的替代方案

拒绝相信自报 PASS，因为新旧判断不能证明有效性。Lightpanda 可用于文本研究，不能代替图形渲染器。主观可玩性保留为建议，机械分数不能证明趣味或平衡。

## 验证

真实 Chrome 中，叙事、回合制和 Canvas 模板均通过六项检查；缺失控件、绝对资源路径和 CDN 脚本均失败。Host 测试拒绝无签名、变化、缺失或不一致的证据及变化后的构建清单。Studio 在运行中的 Canvas 预览旁显示 QA 状态。[工作台决策](2026-09-03-creative-workbench.zh.md) 继续拥有 Session、权限、凭据和作业职责。

## 影响

本地需要 Chrome 和 Node 22+。画面变化不证明画面正确，五个 seed 也不能证明穷尽可达性。Host 密钥在重启后失效。
