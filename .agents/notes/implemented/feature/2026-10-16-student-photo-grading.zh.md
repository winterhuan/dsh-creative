# Agent Note: 拍照转录草稿与家长确认

Status: implemented

[English](2026-10-16-student-photo-grading.md) | 中文

## 问题

此前卷面照片由模型直接通过 paper-result 写成纸上结果：一次识别错误会直接进入错题本和复习计划，没有任何逐题人工核对；面板只能事后改判，不能先核对转录。排查这条链路时还暴露出一个独立缺陷：家长「学校进度」表单提交 `school-progress`，而工作区路由的动作白名单里没有它，表单一直报 403；客户端测试走假后端直接调用归约器，从未经过路由闸门。

## 决策

新集合 `paperDrafts`（上限 500，`default([])` 兼容旧档案）逐题保存转录草稿：练习单、题号、转录的回答、判读结果（含未判定）、帮助程度、疑点和可选错因。`paper-draft` 是模型写入草稿的唯一途径：校验练习单与题号、拒绝已作废的卷、替换时保留原收到时间、相同重试幂等。`confirm-paper` 是家长的入库途径（面板经路由走同一动作）：每条带题号、结果、可选回答、帮助程度与错因；必须有草稿或先前的记录；入库复用 `gradeItem`，反馈为「家长核对照片转录」，并沿用草稿的收到时间，因此改判替换、复习升阶与练习错题创建与 grade-sheet 语义完全一致。允许部分确认，被确认的草稿随即清除，整批重发幂等。家长在答错的题上选了错因时，同时写入已关联的错题，而不只是新建的错题。路由白名单补入 `school-progress`（修复 403）、`classify-mistake` 与 `confirm-paper`；`paper-result` 全面退役：命令、工具描述、技能参考、提示词与测试同步替换。工作台的练习单区块新增「待核对转录」区：逐题可改回答、选判读结果与错因，并有「确认入库 · N」按钮；dashboard 的练习单投影带 `drafts`。

## 考虑过的替代方案

**继续由照片直接写纸上结果。** 更快，但一次识别错误不经核对就进入复习——家长核对环节存在的意义正是挡住这种情况。

**增加 OCR 服务。** 结果与错因仍要人工核对，还会引入本包刻意避免的依赖。

**让模型转录后自行确认。** 确认文字必须引用家长的真实陈述；自行确认会破坏证据边界。

**把草稿并入 paperResults 标为待确认。** 两者生命周期不同（草稿被消费、结果被替换），混在一起会让所有既有查询和容量规则复杂化。

## 验证

宿主测试把此前全部 paper-result 流程改写为 draft→confirm，并断言收到时间保留、反馈文案、升阶、答错建错题、部分确认、幂等重试、无转录拒绝与错因覆盖；面板流程由客户端测试覆盖，包括错因下拉与写入已关联错题的错因。路由测试断言 paper-draft 对 UI 保持 403，而学校进度、错因归类与确认入库返回 200。插件测试覆盖原生存储路径。界面未在真实 DSH 浏览器验证。

## 影响

每个拍照结果都需要家长一次确认才进入复习，这是有意付出的成本。草稿是一次性工作区（500 条约合 62 张满卷），从不计为证据。旧版插件读新状态文件会被 strict schema 拒绝，对本单工作区包可以接受。
