# Agent Note: 小说生成必须优化读者价值

Status: implemented

[English](2026-09-22-novel-reader-value-generation.md) | 中文

## 问题

本决策针对以下基线问题；这些测量描述的是当时的流程，不代表当前检查行为。

Creative 小说写作流程会检查文件结构、追踪状态、细纲消费、AI 模式、标点和连续性，但章节提交不会阻断于读者价值审查。`story-review` Skill 已使用题材化标准检查读者兴趣和翻页动力，但 `storyctl.py chapter check` 不会消费该审查结果；章节仍可能在没有具体开篇承诺、有效冲突、主角选择、状态变化或下一页问题时通过。当前流程还禁止在细纲薄弱时新增独立剧情，因此薄细纲会被扩写成更长的摘要，而不是退回修复。

写作 Skill 与 `narrative-writer` Role 会加载大量参考资料和许多强制性技法；仅长篇写作 Skill 就带有 46 份参考文件，连同 `SKILL.md` 约 31 万字符。固定事件密度、按百分比分段、重复钩子公式、道具重复出现规则和去 AI 味指令，会与当前题材和读者承诺竞争。因此流程可能只是把一种问题换成另一种问题：文本没有明显 AI 腔，却仍然模板化或情绪平直。`narrative-writer` 负责正文与局部改写，`story-review` 负责实质内容审查，确定性的格式和追踪检查由现有工具执行；目前提交路径没有消费结构化的读者价值审查结果。

真正会阻断章节的确定性检查，拦下的是常见的人类写法，放过的是稍加改动的机器文本。在八部合计约 4.5 万字的公版作品上，`check-ai-patterns.js` 报出 52 处 blocking，其中 42 处是破折号，八部里只有一部能通过；在较短的文学样本和手写样本中，24 处破折号命中有 14 处位于台词内。`chapter check` 同样把 `normalize-punctuation.js` 的检查当作阻断项，而归一化把这些副本里台词中的省略号和破折号全部改掉，把一句被打断的话改成完整的句子；[anti-ai-writing.md](../../../../packages/creative/story/knowledge/story/references/agent-references/anti-ai-writing.md) 却记录番茄高分样本 305 章中有 281 章使用省略号，并明确反对零容忍硬禁令。反方向上，「不是A而是B」的同义变体、排比和升华式总结都没有被抓到；在三篇埋入 AI 腔的样本上只改动 1.4% 到 5.8% 的字，所有 blocking 就全部清零，其中一篇通过真实的 `chapter commit` 入库。一篇有连续性错误的较弱真实短篇得分为零；一篇得分为零的较强真实章节带着新的重复套路：顶针句式每千字 15.7 处，而人类样本最高只有 3.3 处。这与规避压力催生新套路的推测相符，但一篇样本不能证实因果。

每个 Role 也都运行在 Session 的模型上。[role-tool.ts](../../../../packages/creative/creative/src/role-tool.ts) 启动 Role 时不传 `agentOptions`，于是上游 [child-agent.ts](../../../../upstream/packages/subagent/subagent/src/child-agent.ts) 让子 agent 继承父 agent 的提供方、模型、推理强度和 token 上限。写出一章的模型因此带着同样的习惯审查这一章，也无法让审查者使用比写作者更高的推理强度或另一个模型。`story-zhuque` 生产入口提供 AI 文本检测分数，作为信息有用；但考虑到模式检查被规避得如此容易，一旦它成为验收目标，就会把写作者拉向检测器。

## 决策

### 读者价值证据决定章节提交

`story-review` 根据题材和细纲审查最终章节。`chapter commit` 与 `chapter accept-current-length` 要求批准评审，包含七类证据：开篇钩子、承诺、冲突、主角选择、状态变化、兑现与下一页问题。每项包含摘要、位置和逐字引句。工具校验必填字段、当前正文哈希和引句存在性；评审者判断证据是否支持结论。缺少承诺、能动性、变化或续读价值时必须拒绝，不能用较低总分代替。

### 先有细纲，再执行场景

细纲检查器在正文存在前要求读者期待、目标、阻碍、选择、后果、兑现和章尾问题。它拒绝缺字段与占位符；工作流另行把抽象陈述退回修纲。写手收到从批准事件导出的紧凑场景计划。战术、潜台词、证据处理和微障碍可以服务已有事件，独立事件、揭示与后续义务则须先修改细纲。

### 写作、连续性与评审各有归属

`narrative-writer` 写正文并局部修订。`story-review` 向 `story-architect` 获取读者价值证据；`consistency-checker` 检查事实、角色状态和伏笔。确定性工具负责格式、退化和追踪。写手只接收选定的题材、情绪、节奏指导及相关例句。参考仍可按需读取；固定密度、章节占比、道具三次出现和钩子公式是可选技法，不是通用验收条件。 [六技能决策](../simplification/2026-09-30-story-skills-native-resources.zh.md) 明确单会话降级：主会话另行完整评审，记录 `role=solo` 和实际配置，不宣称独立评审。

### Role 声明模型选项

打包 Role 的 frontmatter 接受经过校验的 `agent_options`，用于提供方、模型、推理强度和 token 上限。`creative_role` 将选项传给 DSH；调用模型不能通过工具参数提供它们。审查 Role 选择 high 推理强度，写手继承 Session 模型。结果优先报告本地子 agent 已记录的请求配置，否则报告启动时解析出的配置。评审证据记录此配置。[工作台决策](2026-09-03-creative-workbench.zh.md#composition-and-knowledge) 继续负责工具、工作区与权限。

### 模式与检测结果仅供建议

所有 AI 模式规则都是 advisory，包括同义否定对比和相邻句首尾重复。JSON 报告包含全文命中密度；单次命中和密度都不决定验收。[回归语料](../../../../packages/creative/creative/tests/fixtures/novel-pattern-corpus.json) 将公版摘录与合成对话、植入的规避变体分开。测试在这些标注样本上计算规则 precision 和 recall，并确认模式命中不能阻断。未来的阻断式模式规则需要更广泛的人类文本校准；小语料集不能证明普遍准确性，也未打包获得授权的当代真人网文语料。

标点默认保留。项目可在 `设定/写作检查.json` 选择 `normalize-narration`；显式归一化仍保留引号内停顿。写作和精修中的朱雀分数都只作诊断，既不授权提交，也不触发重试。退化与检查器执行失败仍阻断。

### 续写保存紧凑评审证据

追踪状态版本 5 保存每章正文哈希、评审配置和五项摘要：已兑现承诺、主角行动、状态变化、未偿还期待及剩余风险。最后提交章的摘要进入续写上下文。版本 4 读取时不伪造评审，下次事务升级版本。完整证据留在保留的事务输入中；摘要仍是派生评审意见，不额外建立故事事实。

## 考虑过的替代方案

**更多禁词或强制公式。** 否决：词式清理已经会误伤真人写作，且容易被规避。更多模板可能压缩表达，却不增加读者兴趣。

**细纲薄弱时自由编剧情。** 否决：这会产生未批准的连续性义务。先修细纲，同时允许服务批准事件的场景级创造。

**跨题材统一质量分。** 否决：悬疑、感情、治愈和成长小说承诺不同体验。共用证据字段让决定可检查，而不依赖通用分数。

**只做最终评审。** 否决：写后评审不能代替细纲缺失的选择。细纲就绪、连续性和确定性检查保留独立职责。

**检测分数低就接受正文。** 否决：少量文字改动就能清除模式命中，却未必改善章节，因此检测不能成为写手的目标。

**评审始终继承写手模型。** 否决：这让审查绑定写手的习惯。固定版本 DSH 支持宿主拥有的子 agent 模型选项，无须将模型选择权交给调用方。

## 测试

定向可执行测试覆盖两条提交命令、拒绝或不完整证据、过期哈希、虚构引句、成功提交与修订、细纲缺项、项目标点策略及版本 4 续写。Role 测试覆盖选项解析、无效配置和向 DSH 传递审查强度。公版与合成样本覆盖诊断误报和植入变体。这些是不需要密钥的协议回归，不测量模型判断或商业读者反应。

## 后果

读者价值判断仍可能出错。明确的探索请求可以产出草稿而不推进追踪；正式提交仍须评审。创作者有异议时可以修改细纲或保留草稿，但不能静默绕过验收。按需参考可能需要后续定点读取。独立审查配置可能更贵，也可能与写手意见相左；提供方实际行为和正文质量仍需真实模型评估。版本 5 是项目文件变更，与 DSH Session 持久化分开；旧追踪读取器不能消费它。
