# Agent Note: 学生状态读路径缓存与掌握度口径统一

Status: implemented

[English](2026-10-25-student-read-path.md) | 中文

## Problem

工作台每 3 秒轮询一次工作区接口，每次都重新读取并全量校验 `.study/state.json`（上限 8 MiB、两万条作答）、重放复习排期，再各跑一遍 `studyStatus` 与 `studyInsight`；带跨年级摸底范围时 `diagnosticFor` 内部又完整重算一次 `studyInsight`，而它对每个学习目标都要过滤全部作答。`objectiveOf` 在当前册找不到目标时会逐份构造十二份知识地图的解析数组再查找，`studyStatus` 对每条纸上结果都调它。学期数据接近上限时轮询明显变慢。

更严重的是掌握度推导写了两份且已经分叉：`studyInsight` 认为「从未独立答对且近期答错一次」即为需要加强，`diagnosticFor` 的跨年级副本没有这条规则，优先级公式也少了反复错因项——同样的证据，本学期洞察和跨年级摸底给出不同的判定，与 SKILL 宣称的「从未独立答对的目标只要答错一次就标为需要加强」不符。`queryStudy` 的查询链还把未知 kind 静默当成作答分页返回。

## Decision

推导只有一份：抽出 `masteryOf`，本学期洞察与跨年级摸底池共用同一规则（含近期答错即薄弱、反复错因加权优先级），跨年级目标改由同一函数构造；补回归用例锁定「一次答错在剖面与跨年级口径下同为 weak、且不再进入深度摸底的复测样本」。

读路径按成本分层。正式文件读取器以稳定目标身份和真实文件版本缓存严格解析的实体，组合工作区之前核对目录成员。共享证据索引把学习段和练习单的作答关联到各自评分；`objectiveOf` 使用懒构建的知识地图全局索引，`diagnosticFor` 接受预先算好的洞察。`src/learning/queries.ts` 中的共享查询按已观察版本和查询选项缓存投影，直到下一时间阈值；已学分钟数单独刷新。上海午夜、复习到期时间和证据时间窗边界即使没有修订号变化，也使相关投影失效。Student 资源提供器跟随生成的 Remote 快照与原生重连，失败读取保留值并显式标为过期，释放时等待流结束。`queryStudy` 对未知 kind 显式报错，集合查询使用自有键检查。

## Alternatives considered

**只在服务端按标签裁剪 dashboard 载荷。** 需要共享客户端与服务的字段约定，虽能减少传输量，却不能代替版本稳定的解析复用和统一掌握推导。共享查询负责选择各自所需的投影。

**洞察结果按状态加粗粒度时间桶缓存。** 证据时间窗与到期时间可以在桶内变化；显式刷新阈值保持这些时点准确，并复用稳定的解析与索引。

**把缓存做进路由层。** 工具、类型化查询和只读文件消费者共用读取与查询所有者；仅在路由缓存会重复校验和证据处理。

## Consequences

原单状态文件的合成基准包含 3000 条作答、200 条错题，测得完整跨年级 dashboard 约 17ms、未变化条件轮询约 0.1ms；这些数据不衡量实体文件资源路径。当前回归锁定稳定版本复用、未改修订号的直接编辑及时间阈值刷新。跨年级摸底不对薄弱目标安排复测样本，与教学停留在未满足目标的规则一致。工具与面板读取同一套证据规则。

练习单网页化与图形单源见[同名决策](2026-10-25-student-worksheet-html.zh.md)；仓库与真实 DSH 验证归 [HANDOFF.md](../../../../HANDOFF.md) 所有。
