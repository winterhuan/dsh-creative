# Agent Note: 学生状态读路径缓存与掌握度口径统一

Status: implemented

[English](2026-10-25-student-read-path.md) | 中文

## Problem

工作台每 3 秒轮询一次工作区接口，每次都重新读取并全量校验 `.study/state.json`（上限 8 MiB、两万条作答）、重放复习排期，再各跑一遍 `studyStatus` 与 `studyInsight`；带跨年级摸底范围时 `diagnosticFor` 内部又完整重算一次 `studyInsight`，而它对每个学习目标都要过滤全部作答。`objectiveOf` 在当前册找不到目标时会逐份构造十二份知识地图的解析数组再查找，`studyStatus` 对每条纸上结果都调它。学期数据接近上限时轮询明显变慢。

更严重的是掌握度推导写了两份且已经分叉：`studyInsight` 认为「从未独立答对且近期答错一次」即为需要加强，`diagnosticFor` 的跨年级副本没有这条规则，优先级公式也少了反复错因项——同样的证据，本学期洞察和跨年级摸底给出不同的判定，与 SKILL 宣称的「从未独立答对的目标只要答错一次就标为需要加强」不符。`queryStudy` 的查询链还把未知 kind 静默当成作答分页返回。

## Decision

推导只有一份：抽出 `masteryOf`，本学期洞察与跨年级摸底池共用同一规则（含近期答错即薄弱、反复错因加权优先级），跨年级目标改由同一函数构造；补回归用例锁定「一次答错在剖面与跨年级口径下同为 weak、且不再进入深度摸底的复测样本」。

读路径按成本分层：`studyStore` 以观察到的文件版本为键缓存已解析、已校验、已重放的状态，命中即跳过读取与校验，任何写入或外部变更使缓存失效；作答证据改为单遍建立目标索引（作答与纸上结果一次归类），`objectiveOf` 改查懒构建的十二图全局目标索引；`diagnosticFor` 接受调用方已算好的洞察，`dashboard` 一次请求只算一次。时间状态抽出为 `timeStatus`（只依赖学习段与时长设置），轮询请求携带面板正在显示的修订号，证据未变化时只返回 `serverNow` 与新的时间状态；客户端记住本次数据对应的查询签名，同签名同修订号的周期轮询走条件请求并只合并时间字段，查询参数变化、变更提交与手动刷新仍取全量。`queryStudy` 对未知 kind 显式报错，集合表用自有键检查，不再被原型键穿透。

## Alternatives considered

**服务器端按标签裁剪 dashboard 载荷。** 需要拆分客户端与服务的字段契约；条件轮询已把未变化轮询的成本降到一次 `timeStatus`，裁剪留到确有需要时再做。

**洞察结果按状态加时间桶缓存。** `studyInsight` 依赖时间窗（14 天帮助、10 天停滞），桶粒度会引入到期判定偏差；单遍索引加每请求单算已足够。

**把缓存做进路由层而不是存储层。** 工具执行与路由都要读状态，放在 `studyStore` 两边同时受益。

## Consequences

3000 条作答、200 条错题的合成状态下，带跨年级范围的完整 dashboard 约 17ms，未变化轮询的服务端开销约 0.1ms 且不再携带整份知识地图载荷（此前每 3 秒约 60–80KB）。跨年级摸底对薄弱目标不再排复测样本，与今日建议的「需要教学就停在目标上」一致。条件响应对模型工具不可见；`study_status` 的返回不变。
